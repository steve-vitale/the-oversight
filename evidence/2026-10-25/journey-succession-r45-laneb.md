## Metric review (§14 — revisions for the NEXT run, never re-scored here)

- M3v2 loot-line softness: v2 admits any say line naming the dead bearer,
  including inventory lines. 26002's v2 count of 2 = one day+3 marker beat
  (village narration, defensible as echo) + one LOOT line ("You take
  unknown nuts, stick, stick, stick from Tanya. Your hands know what they
  did."). 26002's old-filter count was 0, so its v2 "mentions" contain zero
  villager-talk mentions. PROPOSED: next run reports v2b = v2 minus
  take/loot/inventory-transfer lines (e.g. exclude /^You take .* from
  <name>/), alongside v2; the M3 bar moves to v2b. This run's M3v2 stays GO
  on the letter as pre-registered.
- "Alive at funeral" operationalization: the prereg's phrase is implemented
  as "alive in the immediate post-death roster" because vouch lines fire
  inside the death machinery — a voucher alive right after the kill was
  alive at vouch time. Died-in-between is therefore measured pre-kill ->
  post-death, not pre-kill -> funeral day. The binding rule (FAIL only if
  eligible + alive + silent) is unchanged.
- OfficeDaily granularity: the series is per runDays-call, not per calendar
  day — two entries can share a dplus (26004's probe showed two d+18
  moves: 22 -> 31 then 31 -> 14 within one day). Same-day moves share one
  day census. The office entry can swing wildly within a day (+9 then -17);
  daily snapshots understate its volatility.
- Proof-seed catch (fixed pre-run): the first proof run exposed a verdict
  bug — an EMPTY eligible set fell through to "OPEN-all-died-unknown-cause"
  instead of n/a. Fixed (empty set -> n/a-none-eligible) and re-proven
  before any real seed ran. The bug would have misreported every
  low-trust seed (26001/26002 included).
- V1's died-between branch and the trust-mutation trap remain open items
  for a future succession run (see "Blanks" above).
