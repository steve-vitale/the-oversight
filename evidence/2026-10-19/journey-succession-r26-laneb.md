## Village assessment (plain words)

Five villages, all alive at day 30–32. The mantles all passed cleanly — new
bearers stepped into functioning villages and kept them functioning. What the
runs show, seed after seed: competent players keep their word. Across 17
honest favor commits, not one promise was still open when death came — the
village's daily life (food shared, wounds tended, work done) keeps promises

unfinished ASKS — questions asked, never answered — and those the village
brings back to the successor by name. On 8102 the village also showed the
other side: the successor took up a dead woman's pantry run with empty hands
and an empty pantry, and the promise rotted in front of everyone. Nobody
pretended otherwise.

## Blanks filled / documented (no src/js changes this run)

**1. The stamp-wipe investigation → NOT A BUG, documented.** On 8105 the
released favor lost its `inhFrom` stamp overnight (id `-18-12` → `-18-13`).
Root-caused: the need kind changed (heal_help → food_share), so the opener
took the fresh-build path and `convoStoreFavor` overwrote the stamped
instance. This is DESIGNED — a new need is a new ask in the successor's
era, correctly unstamped (r25's silent-moot finding #1, deliberately left,
is the same class). Proof script:
`scripts/proof-talkround-stampwipe-20261019.js` (committed with this run —
reproduces the stamp-wipe via a zero-exchange talkTo/endConvo).
**Harness fidelity note:** the competent policy's daily `talkRound` opens a
real convo and closes it with zero exchanges, running the full opener
machinery. In the REAL game the opener line is always displayed, so nothing
is "unheard" — the beat is delivered on sight. Only a blind sim driver
misses it. No game change needed; sim drivers should read talkRound
transcripts.

**2. Census-key conflation documented.** `promisesReleased` mixes two
honest paths: playerDeath releases (the open-book beat's trigger) and
betrayal.js's NPC-removal releases ("The promise you made X isn't broken —
it's just unkeepable now" — pre-existing r9 design, working). The harness
now records `releasedAtHandoff` (kept='released' + inherited flag) as the
M2 source of truth. No game change.

**3. Driver honesty fixes** (scripts only): the dlg:commit fallback leak
(committed at trust 8 via the ungated generic fallback — fixed, gate now
applies everywhere); phase-2 two-pass honesty (the driver commits to a
re-ask ONLY having heard the inherited line in-fiction or read the
open book — no driver omniscience); commit-pick trust instrumentation.

## Findings for Steve (design calls)

1. **Should the commit UI warn when you can't fulfill?** (8102: the
   successor promised a pantry run with zero food in inventory and zero in
   the pantry; it broke.) The game lets players promise what they can't
   deliver — that's player judgment, and the break was honest. But a
   competent player CAN see their inventory. A quiet "you have nothing to
   give" beat at commit time would be honest, not hand-holdy. Your call.
2. **The re-ask window is narrow by design** (needs churn in 1–2 days; r25
   1/4, r26 1/4 organic favor re-asks). The open-book beat now covers the
   knowledge regardless. No change proposed — noting the two beats are
   complementary, not redundant.
3. **The promise-break net cost measured -4** (44→40 over the break window;
   the code penalty is -15, the window is noisy with concurrent trust
   movement). If you want the true isolated break cost, that's a targeted
   probe, not this run.
