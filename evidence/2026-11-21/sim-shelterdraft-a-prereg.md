## The question (finding #2599 stays OPEN on the sheltered 16)

The draft-miss diagnosis proved the draft's reachable pool is zero because the only holders in earshot are sheltering: on the draftmiss band, 16 of 85 unarmed-lead wave-4+ launches had exactly one living armed holder and she was sheltering in the hall on (5) or next to (11) the fight tile every time. The holdersupply band shows the same shape (16 sheltered / 16 present). But §10 of the diagnosis shows the shelter rule is only half a wall: shelter blocks the tick's pre-positioning, NOT the fight itself — the sheltered holder charged in on a shout on day 128 and hit hard (867 damage). The draft refuses sheltered holders outright; the fight does not. This arm builds the lever the diagnosis named second: let the draft call a sheltered holder the way a shout does.

## The lever (frozen design)

**SHELTERDRAFT=1** (default OFF). One shape only: the SHELTERED-HOLDER DRAFT. In `villagerMonsterTick` (`src/js/game.js` ~21090), after the 0.5 coin flip passes (a fight is happening) and when the monster's wave is ≥ 4, if the picked lead is unarmed (no loaded searcaster — no searcaster, or an empty one) and a living armed searcaster holder is SHELTERING in the hall on the monster's tile or an adjacent tile (Chebyshev ≤ 1), that holder LEADS the fight instead of the picked lead. On-tile sheltered holders first (roster order), then adjacent (roster order). If no sheltered armed holder is in earshot, or the picked lead is already armed-loaded, the old pick stands exactly as before.

An armed holder: a roster villager (never the scholar), whose equipped ranged weapon is a searcaster, carrying ≥ 1 fusion cell, village health > 20, IS sheltered (`Game.isSheltered`), NOT post-flee resting. The draft helper is `Game._shelterDraftLead(npcIds, m, leadVid)`; it returns `{ vid, fired, holder, reason, dist }` (vid null when it does not fire, with a frozen reason code). The tick uses it only when SHELTERDRAFT=1 and the monster's wave is ≥ 4. The 0.5 coin flip, the table-sanctity return, the player's-tile skip, and the sheltered / post-flee filters on the pick are untouched — the lever acts only inside a fight that was already going to happen, on a lead pick that was already going to be made.

**Why lead, not ally.** The shout path supports allies joining — but allies never volley (holdersupply §6: the volley is lead-only; 0 volleys from armed allies across three bands, including the day-128 shout-join where the holder dealt 867 melee damage and the gun never fired). Joining as an ally would repeat that shape exactly. The draft must make the holder the LEAD, mirroring the presence draft's lead-swap (the tick-level analogue of the shout's call-out: the holder answers a call and comes to the fight — the shout's own mechanism, with the lead seat instead of the ally seat so the gun speaks). No new summoning system: no node move, no unsheltering (the holder stays sheltered in state after the fight, exactly as after a shout-join), no new fight path — the fight runs through the existing `resolveWildMonsterEncounter` with the holder as `vid`.

**Narration.** One line, unshifted onto `rec.log` in `resolveWildMonsterEncounter`'s finally (next to the lend lines, so it reaches the summary the same way theirs do), only when the draft fired: `<HolderFirst> comes out of the hall, Searcaster in hand — 'I'll take this one.'` The tick passes the draft through `opts.shelterDraft = { holder, replacedLead }`. The encounter's own narration otherwise names the holder as lead, as the presence arm's did.

**Draw-neutrality (by construction, verified in the proof test):** the pick's ONE draw is consumed exactly as before on both legs — the helper runs AFTER the pick and adds zero `Math.random()` calls; the lead swap happens after the draw. Downstream draws diverge after the first fire (a different fighter fights a different fight) — that is the lever's effect, disclosed here, not a hidden stream change. The proof test counts draws around the helper on every fixture and around the tick on both legs.

**NOT built:** widening the earshot (every holder-present launch was already dist 0–1 — draftmiss §14), retiming the tick, unsheltering holders as a standing rule, or the supply lever (finding #2599's first lever — a different arm's job; this lever recovers at most the sheltered launches, and says so).

## Primary metric (BINDING, §14)

**GO iff ALL hold:**

1. **Instrument validity — fixtures 100%.** `scripts/test-shelterdraft-a.js` passes every assertion (helper fixtures, live drafted-lead volley, draw neutrality, gate identity); the analyzer `--selftest` passes (new judge shapes incl. the fire-rate floor and the starvation/median guardrails).
2. **Primary — the gun speaks from the front.** Arm-leg sheltered-holder-led (drafted) searcaster volleys **≥ 2**, vs control-leg armed-lead volleys (expected 0 — no holder has ever led a wave-4+ fight on any band in this chain). If the control leg shows armed-lead volleys > 0, the judged number is arm − ctl and the bar applies to the increment; the surprise is reported, not hidden.
3. **Floor — the draft recovers the launches it was built for.** The draft fires on **≥ 50%** of eligible evaluations on the arm leg (eligible = wave ≥ 4 AND picked lead unarmed AND a sheltered armed holder in earshot). If eligible evaluations < 4 on the arm leg, bar 3 is UNJUDGEABLE and the verdict is NO-GO (PARTICIPATION) — the pool did not show up on this band; the lever was not exercised.
4. **Guardrails (scalemetric deciding bar).** Arm-leg villager starvation deaths **≤ ctl + 2** AND arm median survival **≥ 0.8 × ctl median**.
5. **Coverage — the pool is classified.** `v4draftMiss` rows for ≥ 95% of unarmed-lead wave-4+ real fights on the control leg (denominator derived independently from `v4encounters`, same choke-point join as `nearMissStats`), ≤ 5% unclassified; `instrumentErrors` 0 on all 16 seeds; `v4lends` empty on both legs (LEND off).

**Verdict ladder (frozen):** GO = all five hold → the lever lands (game-code commit with `[needs-eyes]`, it changes who leads fights). NO-GO = any bar misses → the game code is REVERTED before commit (instrument + evidence only), classified per §14a: PARTICIPATION if the pool did not show (bar 3 unjudgeable / eligible < 4); CONCEPT-DEAD if the draft fired at rate but the volleys did not follow (mechanism staged, metric fair, concept failed); METRIC-BROKEN if a bar proves unachievable or mis-scoped. A GO met with a guardrail breached is NO-GO.
