## F-ITEM — dead alien contact whispers after death (FIXED)

**Finding.** On seed 107583, Rosa was the village's alien contact (the
villager the alien players whisper dream warnings through). She died d90
in the betrayal fight — instrument-confirmed (`rosa_mendez`, d90, cause
combat, fightLive). The next dawn the game printed: "💬 Rosa says: 'They
said you're doing well. It sounded... proud? Can they feel proud?'" A dead
villager speaking in the present tense, with no framing.

**Root cause.** The 2026-10-09 fix guards this two ways: contacts are only
established with the living, and `apContactWarning` releases a contact who
died since establishment — `if (cvp && cvp.dead) { delete ap.contactedVid;
return false; }`. The guard reads `vpOf(vid).dead`, the data-record flag.
But **no combat death ever set that flag**: `tbDamage`'s hostile branch
(betrayer killed in the fight) says the kill line, fires the murder event,
and calls `registerDeath` — but never `tbVillagerFalls` and never
`removeVillager('killed')`; `tbVillagerFalls` (villager fallen to a monster)
removes the villager from the roster but never marks the record either.
Only `removeVillager('killed'/'ambushed')` and the alien-kill paths set
`rec.dead`. So every combat death left a corpse that still read as alive
to `vpOf().dead` — and the dead contact kept whispering. The betrayal.js
comment says it plainly: "vpOf(vid).dead ... must not lie about a corpse."
It was lying for every combat death.

**Fix** (`src/js/corpses.js`, `registerDeath` — THE death hook, "call
whenever someone/something dies"): mark the villager record dead for kind
person/villager with a villagerId, mirroring the betrayal lookup
(`data.villagers`, then `background_survivors`), plus `rosterChars`,
which `vpOf` falls back to. One place, every death path.

**Proof** (`scripts/test-apcontact-dead-whisper-r275.js`, sim-harness,
seed 107583): three death paths, one question each — does the dead contact
keep whispering?
- Before the fix: A hostile-combat FAIL (vpOf.dead=false, dead contact
  spoke), B villager-combat FAIL (vpOf.dead=false, dead contact spoke),
  C removeVillager-killed PASS (control — the guard already worked there).
- After the fix: ALL PASS (vpOf.dead=true on all three paths, warning
  silenced, contact released).

**Scope note.** The fix also aligns `isMember()` and party skips, which read
the same flag — a combat-dead villager no longer reads as a living member.
No deed gate, table price, or win path touched. No `[needs-eyes]`: a small
correctness fix, not a feel change.
