## Fixes (this run)

### 1. WARN-HEED instrument — the deepen arc was invisible to the watch

Finding: seed 109001 d36, Victor, warn_you engaged (dlg:heed pressed) but no
warning delivered per warnLog. Investigation (probe replay, byte-identical seed):
Victor's heed was his 4th, so the handler took the DEEPEN branch
(convo-dialogue.js, heeds ≥ 4 — the 5-line deepen pool) and spoke "...I keep
seeing it. Whatever it was, out past the treeline. I don't want to be the one
telling the fire you didn't come back." The deepen branch never calls
convoWantWarning, and the warnLog instrument only logs convoWantWarning returns
— so the delivery was invisible to the watch. **Instrument gap, not a game
defect:** the game spoke the warning; the watch could not hear that path.
Victor had warned the player all along (warnLog holds his d14, d18 ×2, d23
deliveries); d36 is the deepening of the same arc.

Fix (instrument-only, no src/js change): the driver records the line returned
for each dlg:heed / dlg:details press (`rec.heedLines`); the analyzer names a
sitting NAMED-VIA-DEEPEN when a recorded heed line matches a deepen-pool
substring. The three generic ACK fallbacks match none of the substrings, so a
heed that fell back to generic still reads UNNAMED — the r150 defect shape,
unchanged.

Proof: `scripts/test-warnheed-deepen-r274.js` (12 pass) — the 4th heed speaks a
deepen line, warnLog gains no entry from it (the blindness, stated), the line
matches the analyzer's substring rule, no ACK line does. The test also
re-proves the r140 deepen arc on this base.

**The r140 test was stale and is fixed in the same commit.** Its "heeds 1–3 are
the 3 distinct ack lines" assertion failed on current master: the r150 fix
changed heed 1 on purpose — the first heed now states the warning via
