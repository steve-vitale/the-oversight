## Failure and repair

A real natural campaign's nested day266/part4 write preceded core midnight
settlement. Code also saved dawn before later God/Journal/temperature hooks,
and Sleep's waking health/energy/conservation came after that save. Unload
could conceal the missing immediate persistence. Clamping a clock or replaying
the night cannot safely reconstruct those effects.

The new timeSettlement module wraps the final synchronous clock/part/day/Sleep
chain after engine initialization. Nested saves sync runtime but return
`deferred` without writing. The outer successful call commits the complete
result once. An uncaught failure preserves the last durable payload and prevents
subsequent autosave/unload of partial memory, returning `settlement_failed`.
The periodic UI says how to reload and Continue; its complete message fits the
phone. Coherent final storage errors can retry. Stale tabs, quota/index errors,
legitimate death/win tombstones and normal save keys remain honored.

There is no new save shape or numerical balance tuning. This protects future
writes; it does not claim exact recovery of an already-written legacy partial
night. Optional hooks that swallow their own semantic errors are not all
certified by a transaction boundary. See TIME-SETTLEMENT.md for maintenance.
