## The one rule

For physical intake, first read [INTAKE-TELEMETRY.md](INTAKE-TELEMETRY.md).
The current metric uses versioned cumulative consumption receipts, with
explicit route equivalents and exclusions. A day ring alone cannot recover
missed meals or old-save history. New food paths need real settlement tests;
reserve credits and food transfers are not automatically meals.

**Compare, never eyeball.**
- Run the same seeds, days and policies **before** and **after** a change, and
  read the difference.
- One run is an anecdote. Use16 matched screening seeds and at least64 distinct holdout seeds for small balance effects.

## Telemetry you can count

Sims keep the **full** stream (`Game.state.telemetry`). The phone keeps only
300 events; that cap doesn't apply to sims.

**Milestones** (`src/js/telemetry-hooks.js`):
- Table: `table_entered`, `table_path`, `table_failed`, `table_won`
- Progress: `arc`, `scale_rank`, `ascension`, `village_lost`
- Builds: `ability_used`, `synergy_active`

**Also:** `death`, `combat_start`, `combat_end`, `contest_end`,
`ability_granted`, and the rest listed in the audit.

Count them in an `extraMetrics(Game)` hook passed to `runComparison` (see
`scripts/sweep-compare.js` header).

## Pitfalls (each one has bitten us)

- **Never run two games in one node process.** Use separate processes;
  `sim-audit.js` shows how.
- **Don't read the bearer's state *after* `tbEnd` / `endDay` / `playerDeath`**
  when a death could have happened inside. A successor has replaced them.
  Snapshot before the call.
- **Single-seed tests are fragile.** If a test needs a specific seed to reach
  some state, pin the state directly instead.
- **Stale green list?** Run `node scripts/check.js` before trusting a sim on
  changed code.
- **Big effects that were silently off are now on.** Forage yield, 23 relic
  perks, villager flank/War Cry, aid fights and more. Compare against
  post-2026-10-14 baselines only.

## Runtime proof fixtures

Load the shared harness once per Node process. Start fresh runs on that Game
for separate scenarios, or use separate child processes when comparing
independent seeds. Choose a landing explicitly when a proof asserts regional
species, parasites or resources; character origin does not fix later landings.

A learned craft still has failure odds. Control the roll when proving the
successful craft/set/catch chain, and separately prove failed attempts consume
materials without granting items or successful-action counters. Preserve one
policy context across actual day resolution when testing daily limits.
`test-trapline-20261011.js` demonstrates these checks with real `endDay()`
wiring. Measure stock immediately before and after the catch: ecology runs
before traps, so yesterday's population is a different denominator. Keep
fixtures within authored carrying capacity unless testing overpopulation.

For time-advancing inventory actions, assert eligibility and actual outcomes
before requiring an event receipt. The shared-runtime test-miser-ledger-names.js
prepares a legal pack, checks capacity and combat state, then measures exact
stock/ledger changes for real donateMaterial and takeMaterial calls. A separate
real overweight fixture must refuse with feedback, move no stock and add no
receipt. Do not interpret a missing receipt alone as an attribution defect.
Original intermittent failures without RNG capture remain causally unresolved;
seeded replacement proof success does not reconstruct that missing history.

Travel targets are candidates, not completed moves. For a location guard,
select an adjacent legal target and verify the actual arrival coordinates
before testing the destination's access rules. A null travelBlockage means the
current approach is unblocked; it does not mean the tile has no blockFrom on
another side. Prepare truly clear ground explicitly when testing no work.
Require each intended obstacle case, actual emitted Game.log feedback and
stock/time effects; conditional success placeholders hide missing coverage.
The shared-kit travel/access proofs demonstrate these contracts. Their old
unrecorded random failures are retained separately from the seeded proof;
do not claim an exact historical replay without its random stream.

Unknown-plant proofs must confirm plantKnown is false; random starting jobs
may already know the species. Use live examineCell and a forageable stocked
patch when proving observation-to-recognition wiring. Unknown harvests enter
hidden-composition lumps, not identified plant stacks. For animal spawning,
prepare or inspect both biome compatibility and local population; a fixed
map coordinate or repeated chance rolls cannot supply either. Check depleted
stock separately and require same-action event emission and real food costs
for failed strikes. The recognition/prey fixture audit retains these prepared
contracts separately from natural-incidence or playstyle viability claims.

For probability contracts, use controlled rolls at the actual thresholds
instead of asserting an ordering between independent small random samples.
`test-miser.js` exercises cache theft below, at, between and above the near
and far rates, including its real day-end caller. Use legal map coordinates
and measure distance to every relevant village. Campaign estimates still
require the matched screening and holdout panels described above.

For food production, observe the actual harvest and its immediate stock
change. Multi-day stock also reflects regeneration, other consumers and
detail initialization. `test-drifter-joinstay.js` keeps the actual day-end
and travel callers while measuring each village's reported takes against
the stock removed. A working harvest call proves that path, not campaign
survival or playstyle viability. Keep this controlled proof instrumentation
separate from passive campaign observers.

Before calling a visible name a knowledge leak, inspect the actual starting
Codex and regional familiarity. Knowledge proofs should declare their blind
and learned fixtures, then exercise the real renderer and action. For reward
proofs, check consumed inputs and actual delivered receipts; a cleared quest
or an `item` reward label alone does not prove that anything was delivered.

Timing proofs should observe the actual methods dispatched and the relevant
clock boundary. Daily grief is not a proxy for part-scale needs. Social
memory fixtures must provide a substantive spoken beat; missing or filler
snippets should remain rejected. When dialogue variants expand, preserve
the resolution and nonrepetition checks while reviewing the authored content.
Run identical static scans once per scenario rather than once per menu item.
