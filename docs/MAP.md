# The Oversight — One Map (unified map doc)

Written 2026-10-28 (fixall-map slice 1c, design §D) to close the canon
silence the travel-scale coherence design named: until now no single doc
said how the home board, the beyond-edge tiles, the nomad leg boards, the
macro map, and the region registry relate. This doc states what the code
does today. Anything marked PLANNED is not built yet and must not be
quoted as live.

## The one-sentence version

The world is one continuous tile map. The home board is where you live;
the ground past its edge is generated by the same deterministic function
wherever you walk; a nomad leg is a region of that same world, generated
from its region seed; the visible window is always 9x9 around you. You
walk everywhere. Nothing teleports.

## 1. The home board (where you live)

- Tiles 0..8 in both axes (`worldSize: 9`). Haven sits at the village
  coordinate (4,4 by default; `state.village.px/py` is the authority, and
  `homeVector()` reads it — never assume 4,4 in new code).
- Generated once per run by `genMap(seed)` from the run seed: creeks run
  top-to-bottom, wetlands hug water, groves cluster, one ruin with a story
  is guaranteed near haven, blockages (fallen tree / rubble / washed out)
  guard approach sides, ~35% of creek tiles need a bridge or a swimmer.
- Home tiles have stock that regrows, wildlife populations, and (ruins)
  finite manufactured loot. A ruin emptied stays empty; a grove regrows.

## 2. Beyond the edge (the world keeps going)

- `map.beyond` is a sparse store: only tiles someone generated live there.
  Ungenerated coordinates cost nothing and return undefined, so every
  existing "is there ground here?" probe keeps its meaning.
- `beyondTile(x, y)` is a pure function of (worldSeed, x, y): same seed
  and coordinates regenerate the same kind, stock, wildlife, and loot on
  every load. Kinds are the landing biome's wild kinds plus a standing
  `building` (10%) — the fringe holds buildings, not farmhouses, and
  home ruins are not repeated out here.
- A `building` scavenges like a ruin with finite loot: repeated pulls
  empty it, and an emptied building says "Picked clean" and stays empty.
  Wild beyond tiles regrow like home tiles.
- The visible window (`mapWindow()`) is 9x9 centered on the player in
  world coordinates. At home it is exactly the 0..8 board; past the edge
  it slides with you. Tiles never re-index — only the window moves.
  Ungenerated beyond coordinates report fog, never generate by looking.
- `travelTargets()` offers home tiles (revealed within 3, or adjacent
  into fog) plus orthogonal-adjacent beyond tiles. Stepping past the rim
  (`tryNodeExit`) generates the next tile and crosses onto it; the first
  crossing says so, once per game, and names the way home.
- Blockage/bridge parity (fixall-map slice 4): deeper wild ground plays
  by the same obstruction rules as home ground — ~12% of wild beyond
  tiles past the first ring carry a fallen-tree / rubble / washed-out
  blockage guarding one approach side, and ~35% of wild beyond creek
  tiles need a bridge or a swimmer. `travelTo`'s intermediate-blockage
  scan covers the path bounding box, not just the home board, so a jump
  from beyond onto a home tile can no longer skip its beyond
  intermediates. Exempt by design: the first ring (Chebyshev <= 5, the
  crossing step) stays open ground, and all city tiles stay open.

## 3. Nomad leg boards (regions of the same world)

- A leg is one region. `enterLeg(i)` sets `state.region` to the leg's
  region and generates the leg board from `legSeedForRegion(regionId)`:
  the RUN seed (the save's worldSeed when present, else the run seed
  stashed on the road at the first leg entry, before generation replaces
  the board seed) mixed with the region id.
- Consequence: two entries to the same region in the same run produce
  the same ground. The old seedless `genMap()` call — a fresh random
  board per entry, i.e. a teleport to a random place — is gone.
- What did NOT change: the road's gate (global rank + a living
  known-region scattered kin), the party, the forfeit (leaving still
  gives up the Table — the travel-vs-departure split is a Steve ruling,
  not built here), and the 3-day living/search wait on a leg (arrival +
  search time, not a teleport timer).
- A leg board is still a 9x9 board with its own haven-centered camp tile
  while you are on it. The home board is not preserved underneath it;
  the road is an ending, not a round trip, until the ruling lands.

## 4. The macro map (what the map screen is, and is not)

- The docs hold two older map notions: a strategic macro map (tap a tile,
  travel there) and the 9x9 detail grid ("YOU ARE IN THE WORLD"). In
  code today there is ONE map screen and it is for VIEWING: it shows
  only tiles the player has seen (`seenTiles`: stood on, or learned by
  comparing maps), and it never moves the player. Steve's law stands:
  no travel from the map; travel happens by walking.
- The 9x9 window (§2) is the detail grid wherever you stand — at home,
  past the edge, or on a leg. There is no second board to keep in sync.

## 5. The region registry (an index, not a parallel world)

- `src/data/regions.json` lists 20 regions (biome profile + people
  layer). `state.world.regions` records which regions are known /
  contacted / visited, and scattered kin are placed in seeded regions.
- A region is an AREA of the continuous map (a set of coordinates sharing
  a biome + people layer), and the registry is the index into it — not a
  separate world with its own maps. That sentence is the design's
  direction; the code today only partly honors it: leg boards are
  region-seeded (§3) but regions do not yet own map areas, and the
  registry's `known` flags are village-level, not per-knower.
- CONSTRAINT ON ALL LATER MAP WORK (Steve's perception law, 2026-10-28):
  knowledge is per-knower with provenance — who heard it, from whom,
  when. A registry entry must never hand a place or a person to a
  villager who never heard of it; gossip spreads knowledge delayed and
  possibly wrong, never instantly to all. Any future far-village ledger
  or leg-village link work must trace to a specific knower (the villager
  who met them, or who was told by a named teller) or it does not ship.
- LANDED 2026-10-29 (gaps2-knower): the knower ledger IS built now.
  `state.village.villageLore[knowerId][villageId] = { how, day, toldBy,
  secondhand }` — `how` is 'visit' / 'seen-nearby' / 'rumor' (granted only
  on delivery/read) / 'told' / 'link'; foreign villages hold polity
  lore as `'village:<id>'` about Haven. The registry's `known` flags
  are still village-level, but learned region grants now record
  `knowerId`/`toldBy` (hearOfRegion opts). Peer proposals (covenant/
  trade) are knowledge-gated like proposeLink (decided call, Steve may
  overrule). What is NOT built yet: auto-spread of told lore through
  conversation gossip (the `tellVillageLore` primitive exists, unwired
  by design), per-knower region display gating, and anything touching
  the road's ending (still waits on Q0(a)).

## 6. The way home (information became action)

- `homeVector()` is the compass data: direction arrow + Chebyshev
  distance from the player to haven. The compass line renders it whenever
  distance > 0, at any distance past the edge.
- `walkHome()` is the action: it walks the player home tile by tile
  through the same `travelTo` pipeline as walking out — orthogonal
  steps only, so every step is a `travelTargets`-offered step; a blocked
  step tries the other homeward axis, then sidesteps perpendicular
  (toward-home side first, never revisiting a tile on this walk), and
  only stops honestly with the block named and the player unmoved when
  every escape refuses; combat, death, or the step cap stop the walk
  mid-way with `reached=false` (tap again after the fight). The compass
  line's "Walk home" button calls it (phone feel is [needs-eyes]).
- COST: walk-home charges exactly what walking out charges. Node travel
  is FREE by the standing rule — the steps themselves cost no kcal;
  the world ticks and encounters on each step exactly as a manual walk
  would meet them. No walk-home tax exists; inventing one is a Steve
  call, not a quiet addition.
- NO TELEPORT, ever: any future "return" that jumps position instead of
  stepping is a revert-on-sight failure of this doc's first paragraph.

## 7. What is still open (honest ledger, not promises)

- City districts as beyond tiles (streets / buildings / plazas / caches)
  — LANDED (fixall-map slice 3): districts generate deterministically
  past the 12-tile wilderness ring, with finite-scavenge buildings and
  caches and walkable pavement. Still open: dens and the city people
  layer (residents/hosts/markets) — held, because both need a
  perception-traced mechanism, not a spawn (see §5).
- Blockage/bridge parity past the edge — LANDED (fixall-map slice 4,
  see §2). What remains open is the city-people layer and dens (see
  below), not the walk rules.
- Villager movement past the edge: every villager system still targets
  0..8; only a villager's RETURN walk may step through beyond
  coordinates (fixall-map slice 2), and only because return retraces
  ground that villager already stands on. Departures, expeditions, and
  meandering stay clamped — no beyond-errand faucet exists.
- Leg villages becoming real registry/link entries, arrival courtship
  advantage, and the far-village ledger (hundreds of villages as registry
  entries, not full sims) — planned, each gated on the knower-trace
  audit in §5 and, for anything touching the road's ending, on Steve's
  travel-vs-departure ruling.
- Starting location: the landing region is still the eastern woodlands
  in practice ("every first run still lands there"). Nothing in this
  doc changes where a run starts, and no run starts in a wasteland.
  Whether starting region changes what survival turns into is a
  measurement question, not an assumption this doc makes.
