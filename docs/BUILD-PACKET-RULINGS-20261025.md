## Principles used

- ARCHITECTURE.md: data, canonical identities and shared resolvers; validate
  references. Its aspirational layout is not proof of current runtime behavior.
- COHERENCE-SPINE.md: real people own builds; NPC/player progression parity;
  finite competing slots. No guaranteed perfect build for a named policy.
- Steve's direct all-playstyle gear instruction in godpath/STEVE-ANSWERS.md:
  combat cannot be the only viable reward economy. This does not promise every
  pure bot policy all content or all capstones.
- TABLE.md core laws: earned, played, losable endings; existing Table sanctity;
  godhood is not mandatory. Keep its explicit seat prerequisites unless a
  separately justified design change supersedes them.
- DIRECTIVES.md: decisions rather than chores; knowledge earned through real
  sources; legible actions and consequences on one phone screen; food remains
  the economy. A bot's missing action is not proof the game lacks the action.
- Steve's difficulty instructions: wins moving either way require investigation;
  day150 already very hard, day180 exceptionally long. No protected infinite
  waiting, target-win compensation, synthetic rewards or output trimming.

Packet measurements are reported observations, not independently revalidated
effect estimates here. Numerical tuning needs current common-controller paired
evidence, not agreement with a recommendation. Specific defaults below remain
provisional levers, not sacred numbers.

## Execution and coordination

Do not batch-implement this table. First audit what latest public code already
satisfies; assign one bounded defect at a time through AGENT-LANES.md and review
branches. Root-cause divergent agent work with a normal reviewed reconciliation,
preserving both histories. The ship loop owns origin pushes and live publication.

Priority: input/save/softlocks and false knowledge/rewards; Table/shelter/muster
boundary defects; actual gear and social-route opportunities; then authored late
content. Keep numerical balance proposals separate from broken verbs.

Each changed runtime boundary needs its real caller, shared-kit positive and
failing controls, current quick/full results, and appropriate actual phone
action/cancel/save/Continue evidence. Survival/progression/reward changes need
the current common observer/controller on both frozen roots, all registered
per-policy domains, matched screening and appropriate holdouts/cohorts. Preserve
failed pilots, censoring and unknown opportunities. Do not certify strict
pacifism from a mixed policy. An easier win cannot erase resource/community
regressions, and a harder fair game is not automatically a regression.

This document changes no runtime, coefficient, collector or save format. It
does not waive existing failing gates or certify any candidate for release.
