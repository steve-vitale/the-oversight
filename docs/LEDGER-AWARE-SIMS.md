# Explicit ledger progression trials

The original maker/merchant/caregiver policies intentionally disable deliberate
hunts. Their stalled progression cannot be blamed solely on capable's faced-bar
logic. Preserve those non-hunting mixed baselines; they are not pacifists.

The separate `ledger-aware-{capable,maker,merchant,caregiver}` profiles compose
the existing paid ending/counter experiments and add deliberate progression
exploration/hunts. This changes player strategy, never the Game's ledger bars,
per-type cap, prices, rewards or numerical pressure. The livelihood variants
are explicitly newly mixed strategies, not baseline bug fixes or proof of
noncombat viability. Existing default families and all their hooks remain.

The layer distinguishes the wave1/2 unlock kill ledger from the Table's distinct
enemies-faced requirement. It checks current configured bars/type caps, including
the separately configured mastery-extra allowance. Once the current unlock bar
is complete it does not hunt for additional ledger points. A healthy and fed
bearer can approach an uncapped type on the actual current rendered field,
reusing capable's real path/encounter flow. It never scores a kill itself.
Missing local opportunities cause one adjacent public travel attempt, using
the existing public-travel committed walking/door/exit layer. Unknown remote
monster positions do not choose the destination. Parent combat, costs and
retreat remain authoritative; no forced combat completion, teleport or grants.

Guards:70% health,40% personal food capacity, day30 or learned sentiment,
one attempt per bearer/day-part, no active fight/contest/pending encounter.
Existing parent hunt attempts retain priority. The new optional shared-approach
guard aborts if bearer/state/current target changes during movement. Context
diagnostics report reasons and actual attempts, not universal opportunity
denominators or successful kills. A capped target may still attack while a
normal paid walk leaves its field; that is not a deliberate capped-type hunt.

## Exact source ablation

`node scripts/prepare-ledger-ablation.js <fresh-external-directory>` copies
the current simulation inputs/static dependencies and switches only
`EXPERIMENT_ENABLED` in ledger-aware.js. Both complete manifests and provenance
are retained; no Git worktree or raw-case copy is created. Root HEAD metadata
does not substitute for the actual manifests on an uncommitted input tree.
The common copier also serves prepare-calendar-ablation.js, whose one-JSON-flag
contract stays unchanged. Never mutate either frozen root during a run.

Run balance-panel against both roots with identical ledger-aware policy IDs,
seeds, observer, node version, flags and horizon. First use selected pilots,
then16 matched seeds/profile and named cohorts; small-effect conclusions need
64 eligible pairs and independent holdouts. Extend observation caps to real
endings. Keep parent livelihood and paid ending/counter families as controls.

The ordinary `balance-panel compare` intentionally REJECTS a changed controller.
Keep that rejection; do not relabel controller improvements as Game-only effects.
For this declared one-file experiment use:

```
node scripts/controller-trial-report.js <off-panel.gz> <on-panel.gz> <ledger-ablation.json> <fresh-report-prefix>
```

This separate report requires the exact constructed source manifests, identical
Game/other controllers/harness/observer/options, actual neutral controls and
all29 metrics with explicit unknowns. It retains the ordinary comparator's
rejection and uses the existing metric definitions/statistics. Its verdict is
always controller_review_required, never Game balance clearance or automatic
default promotion. Unrelated source/harness changes, missing metrics/controls
or mismatched options remain invalid. Job availability trials require a separate
declared selection design; they cannot silently enter this simple trial.
